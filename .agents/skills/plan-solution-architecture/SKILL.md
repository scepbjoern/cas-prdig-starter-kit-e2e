# plan-solution-architecture


Lies Prototype Brief und benötigte bestätigte Quellen. Erarbeite Systemgrenzen, Verantwortungen und Datenflüsse; pro gebautem/gemocktem System ein Repo, unabhängig von Personenzahl.
Erzeuge docs/solution-architecture.md, contracts/interface-*.md, contracts/data-*.md und docs/e2e-scenarios.md aus den Vorlagen. Vereinbare IDs, Datenhoheit, Formate, Fehlerverhalten, feste Ports, URLs, Testdaten und eine frühe kleine Integrationsprobe.
Leite solution.json aus solution.example.json ab. Keine unbekannten Commits oder Repository-Zugriffe erfinden. Technische Vorgaben müssen für Agents ausreichend sein; erkläre Studierenden fachliche Folgen.
Lasse die Architektur samt Verträgen in einem frischen unabhängigen Kontext reviewen. Gemeinsame Aufgaben gehören als führende Issues ins E2E-Repo; keine doppelte Feature-Statusliste.
